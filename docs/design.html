pvault: 1Password to pass, on demand

Owner: Andrew TavaresStatus: draft for reviewTarget: macOS + Homebrew
  • Stack Go + Bubble Tea
  • Sync source mapping file in ~/.config
  • Conflicts ask per entry
  • Env global export by default
  • Store local git, rollback in CLI + TUI
  • Uninstall only what it installed

Context and problem

Shell config loads secrets from pass at startup. Today ~/.zshrc:155 has export PAGERDUTY_API_KEY=$(pass pagerduty-api-key) and the store holds one entry (ls ~/.password-store shows pagerduty-api-key.gpg). 1Password holds the real copies, but the copy into pass is manual and has no history. Each new Mac also needs the same manual setup: install pass, gnupg and the 1Password CLI, create a GPG key, init the store, wire up zsh. There is no clean way to upgrade that setup or to remove it. pvault is one Go binary that does setup, upgrade and uninstall, syncs chosen 1Password fields into pass on request, keeps a rollback history, and has a TUI to view and manage the vault.

Goals and non-goals

Goals

  • One command installs everything a fresh Mac needs and is safe to run again (idempotent).
  • pvault sync copies every entry listed in the mapping file from 1Password to pass, and asks before it overwrites a pass value that differs.
  • Every sync can be rolled back from the CLI and from the TUI.
  • pvault upgrade updates the tool in place and runs config migrations.
  • pvault uninstall removes only what pvault installed. With --purge-vault it also removes the vault.
  • A TUI to browse entries, see sync state and history, sync, roll back, and add, edit and delete entries.
  • Secrets never appear in argv, logs, state files or terminal output unless you ask to reveal them.

Non-goals

  • Two-way sync (pass to 1Password).
  • Linux, Windows or headless machines. Other Macs only, with the 1Password desktop app.
  • A git remote for the store. 1Password is the backup.
  • Sharing one GPG key across machines. Each Mac gets its own key.
  • Scheduled or background sync. Sync runs only when you ask for it.

Options considered

A. How sync picks items

OptionForAgainst
Mapping file in ~/.config/pvaultExplicit names, env vars and scopes. Can be reviewed. Holds no secrets. Each machine can have its own.You write it by hand. Mitigation: pvault mapping add and a TUI picker.
1Password tagNo configPass names come from item titles. No place for the env var or field choice.
Dedicated vaultSimpleSame naming problem. You must move items.

B. Where install logic lives

OptionForAgainst
All in install.shNo build stepHard to test. Upgrade, uninstall and TUI logic split across two languages.
Thin install.sh + pvault setupAll steps in Go with unit tests. The same code runs for install, upgrade and uninstall.The bootstrap needs Go. It installs Go with brew if it is missing and records it.

C. How secrets reach the shell

OptionForAgainst
Global export at shell start (default, per your choice)Same behaviour as today. Every tool sees the variable.The shell decrypts every global entry at startup. Every child process the shell starts inherits the values (checked: PV_DEMO=inherited zsh -c 'python3 -c …' prints inherited).
Per-command wrapper (scope = "command", opt-in)The secret exists only in the process that needs it.You must list the commands that need the secret.
Skip pass, use op runNo local copyNeeds the app unlocked and Touch ID in every terminal (10-min idle, 12-h hard limit, 1Password docs).

D. How sync detects change

Chosen: compare live. Sync reads both sides and compares bytes in memory. Rejected: store hashes in a state file. An offline attacker can brute-force hashes of short secrets, and the hashes still need a live read to confirm.

Decision

A single Go binary pvault (cobra CLI + Bubble Tea TUI). A thin install.sh bootstraps Go, builds the binary and runs pvault setup. A per-machine mapping file lists the 1Password references to sync. Sync is one-way and asks before each overwrite. The store is a local git repo, and rollback adds a new forward commit. Entries export globally by default, and you can set scope = "command" for any entry. A manifest records each change that setup makes, and uninstall reverts only what the manifest lists.

Mapping file

The file is per machine and is not stored in the repo. pvault mapping init writes a commented example. docs/mapping.md explains how to write one. Field references use the op://vault/item/[section/]field syntax. Names may contain only letters, digits, -, _, . and spaces. For any other character, use the item ID (secret reference syntax). The fastest way to get a reference is Copy Secret Reference in the 1Password app.

version = 1
# op_account = "my.1password.com"   # only if you have more than one account

[[secret]]
pass = "pagerduty-api-key"                     # path in ~/.password-store, no .gpg
ref  = "op://Private/PagerDuty/credential"      # Copy Secret Reference in 1Password
env  = "PAGERDUTY_API_KEY"                      # optional
# scope = "global"                              # global (default) | command | none

[[secret]]
pass     = "work/github-token"
ref      = "op://Employee/GitHub PAT/token"
env      = "GITHUB_TOKEN"
scope    = "command"
commands = ["gh"]                               # wrapper: decrypt only when gh runs

Validation rejects these: duplicate pass or env values, a ref that does not start with op://, an env that is not [A-Z_][A-Z0-9_]*, scope = "command" without commands, unknown keys, and a version newer than the binary supports.

Sync sequence

sequenceDiagram
  participant U as You
  participant P as pvault sync
  participant O as op CLI
  participant G as pass + gpg
  participant R as store git
  P->>R: git status clean? record HEAD
  loop each mapping entry
    P->>O: op read -n "op://…"
    Note over O: Touch ID once per terminal
    P->>G: pass show path (if exists)
    alt pass entry missing
      P->>G: stdin → pass insert -m -f path
    else bytes equal
      P-->>U: = unchanged
    else differs
      P->>U: prompt o / s / v / q
      U-->>P: o
      P->>G: stdin → pass insert -m -f path
    end
  end
  P->>R: git tag sync-YYYYMMDDTHHMMSS (if any change)
  P->>P: write state.json, report orphans
  • Secret handling. Values move only through pipes: op read -n stdout into memory, then into the stdin of pass insert -m -f. Argv holds only paths and references. The runner records every argv in tests so we can assert this.
  • Exact bytes. op read -n adds no newline. pass insert -m stores stdin as given. The compare uses the exact bytes.
  • Orphans. An orphan is a path in state.json that is no longer in the mapping. Sync reports orphans and deletes them only with --prune, after it asks you. pvault never touches a pass entry that you made by hand.
  • Dirty store. If the store has uncommitted changes, sync stops and tells you how to commit or discard them.
  • Errors. If 1Password cannot read one entry, sync marks that entry as failed and continues with the others. It exits 2 if any entry failed.

Shell environment

# >>> pvault >>>  managed by pvault; edit ~/.config/pvault/mapping.toml instead
[[ -x ~/.local/bin/pvault ]] && eval "$(~/.local/bin/pvault env --zsh)"
# <<< pvault <<<
  • pvault env wraps each value in single quotes and escapes embedded quotes as '\''. A value such as a'b$(touch x) is set literally and runs nothing.
  • For scope = "command" it prints gh() { GITHUB_TOKEN="$(pass show work/github-token)" command gh "$@"; }.
  • If an entry fails to decrypt, pvault env prints a warning to stderr and skips it. A failure never stops the shell from starting.
  • Setup never changes lines outside the block. doctor and setup report lines like ~/.zshrc:155 so you can move them into the mapping.

Global export keeps today's behaviour: each new terminal decrypts every global entry. When the gpg-agent cache has expired (defaults: 600 s idle, 7200 s maximum, GnuPG agent options), pinentry-mac asks for your passphrase when the terminal opens. The startup time for N decrypts was not measured.

Setup steps (idempotent, recorded in the manifest)

  1. Stop if the OS is not macOS. Require Homebrew.
  2. brew install pass gnupg pinentry-mac and brew install --cask 1password-cli, each only if missing. Record only the packages that pvault installed.
  3. gpg-agent.conf managed block: pinentry-program /opt/homebrew/bin/pinentry-mac, then gpgconf --kill gpg-agent. Skip this step if a pinentry-program line exists outside the block.
  4. If no secret key exists, offer to create one: gpg --quick-generate-key "Name <email>" future-default default 2y. Pinentry asks for the passphrase. Record the fingerprint (GnuPG key management).
  5. If the store does not exist, run pass init <fpr>. If it exists, check that its .gpg-id has a matching secret key.
  6. If the store is not a git repo, run pass git init. This makes a first commit of the existing entries.
  7. Write mapping.toml from the example if it is missing. Never overwrite it.
  8. Add the ~/.zshrc block (back up the file first). Report pass calls outside the block.
  9. Check that the 1Password app integration works. If it does not, print the steps: Settings → Developer → Integrate with 1Password CLI (docs).

Upgrade and migrations. The manifest stores schema_version. Migrations live in internal/setup/migrations.go as an ordered list. Setup runs the ones above the stored version, then saves the new version. A migration that rewrites mapping.toml first saves a .bak copy.

Uninstall

  1. Show the plan: every manifest item, plus items that will stay and why.
  2. Remove the managed blocks from ~/.zshrc and gpg-agent.conf.
  3. brew uninstall each package in the manifest, in reverse order. Skip a package if brew uses --installed lists a package that pvault did not install.
  4. Remove ~/.config/pvault (keep it with --keep-config), ~/.local/state/pvault, and the binary.
  5. --purge-vault: you must type the store path. Then pvault removes ~/.password-store.
  6. --purge-key: deletes the GPG key only if the manifest fingerprint shows that pvault created it. pvault never deletes a key that existed before setup.

Rollback

pvault rollback REV runs git restore --source=REV --staged --worktree -- . in the store and commits pvault rollback to REV. The default no-overlay mode removes entries that were added after REV (git-restore). History is kept, so you can undo the rollback too. --entry NAME restores only NAME.gpg. If .gpg-id differs between REV and HEAD, rollback stops, because the old files may be encrypted to a key you no longer have. It does not run git reset --hard.

TUI

Built with charm.land/bubbletea/v2, charm.land/bubbles/v2 (list, viewport, textinput, help) and charm.land/lipgloss/v2. Views: Vault (tree + detail), Sync (live progress with a conflict prompt), History (sync tags and commits with rollback), Mapping (entries, $EDITOR through tea.ExecProcess, and an "add from 1Password" picker). The detail pane shows a masked value. Reveal shows it for 10 s. Copy uses pass show -c, which clears the clipboard after 45 s. Status values come from state.json and need no decrypt. c runs a live check.

Testing and verification

Gate: make check, exit 0, which runs test -z "$(gofmt -l .)", go vet ./..., go test -race ./..., scripts/check-dep-age.sh and shellcheck install.sh. shellcheck is not installed here (command -v shellcheck is empty), so it is a dev dependency to add.

Harness. Tests run real pass and gpg against a temp GNUPGHOME and PASSWORD_STORE_DIR. TestMain creates a key with no passphrase: gpg --batch --pinentry-mode loopback --passphrase '' --quick-generate-key. op and brew are fake scripts on PATH. They read fixtures and log their calls, because those are external services. HOME is a temp directory.

PackageBehaviour proved (each test fails if the code is wrong)
mappingRejects duplicate pass or env, a bad env name, a ref without op://, command scope without commands, unknown keys, and a future version. Default scope is global.
syncerInserts a new entry. Makes no git commit when values are equal. Leaves the pass bytes unchanged when the Decider skips. Overwrites when it says overwrite. Reports an orphan and deletes it only with prune. A value with a trailing newline round-trips byte for byte. No recorded argv contains the secret value. A dirty store stops sync.
store / rollbackRestore to a tag brings back the old ciphertext and removes entries added later. --entry touches one file only. Stops when .gpg-id changed.
shellenvEvaluating pvault env output in zsh -c for the value a'b$(touch $TMP/x) sets the exact value and creates no file. Writing the block twice gives a byte-identical file. Text outside the markers stays byte-identical.
setupThe fake brew with pinentry-mac missing puts it in the manifest. A second run makes no install call. Uninstall removes only manifest packages and skips one that has outside dependents. --purge-vault with a wrong confirmation deletes nothing. A key created before setup survives --purge-key.
tuiModel Update tests: s starts sync. In the conflict modal, o sends an overwrite decision and s sends skip. Rollback needs the typed confirmation. Reveal goes back to masked after the timer message.

Manual end-to-end on this Mac (the output goes in the PR): ./install.sh, add the PagerDuty entry to the mapping, pvault sync, pvault check; echo $? → 0, then in a new shell [ -n "$PAGERDUTY_API_KEY" ] && echo set, pvault rollback HEAD~1 --entry pagerduty-api-key, pvault uninstall --dry-run.

Risks and mitigations

RiskMitigation
Global export leaks secrets to every child process (npm scripts, editors, agents).You chose this. scope = "command" and pvault run are available per entry. doctor lists global entries.
A shell-quoting bug in pvault env runs code from a secret value.Single-quote escaping and the a'b$(touch …) test.
A setup edit breaks ~/.zshrc.Marker blocks only, a backup before the first edit, [[ -x … ]] guard, and env never exits non-zero.
Uninstall removes a package that something else needs.Manifest only, plus the brew uses --installed check.
Rollback restores files encrypted to a lost key.Stop when .gpg-id differs.
A supply-chain attack through new Go modules.Exact pins, committed go.sum, check-dep-age.sh in make check.
Bubble Tea v2 is new (v2.1.0 is 17 days old).Pin it. Keep the TUI logic in testable Update functions.
Secrets stay in Go memory (strings cannot be zeroed).Use []byte, overwrite buffers after use, short-lived process. We accept the remaining risk.

Alternatives rejected

  • Python + Textual: needs a Python runtime on every Mac.
  • Shell + gum/fzf: weakest TUI and hardest to test.
  • Two-way sync: needs conflict rules in both directions for little gain.
  • Stored value hashes for change detection: an attacker can brute-force them offline.
  • git reset --hard for rollback: destroys history and cannot be undone.
  • A mapping file in the repo: the tool runs on several Macs with different secrets.
  • Prebuilt release binaries: needs CI and an auth flow for a private repo. Building from source is enough for Macs that have Go.
